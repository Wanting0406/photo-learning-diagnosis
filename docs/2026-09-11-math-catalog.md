## 接入行为

- 复用图片初识别的知识点和关键词，不增加在线模型调用。
- 数学目录逐条按初一/七年级、初二/八年级、初三/九年级过滤，中考归初三；小学、高中和不明确的混合年级不匹配。
- 按课程标题及来源知识点精确匹配、保守包含匹配排序，排除“计算、函数、几何”等泛词。
- 备注中明确写一轮或二轮时按轮次筛选；同时出现两者时不强行限定轮次。
- 数学和物理综合排序，共最多 2 节，重复标题合并。两个数学来源独立读取，任一来源失败仍保留其他成功结果并提示。
- 已知学科时与识别并行读取；每科缓存 10 分钟并合并并发读取，完整分页后才缓存。
- 初识别课程结果写入任务，完整分析复用已有结果；存储、导出和原长图匹配兼容。
- 页面“查看目录来源”打开镜像记录，记录内保存原目录链接与原单元格位置。

## 配置与更新

仅本地启动器注入 `BITABLE_MATH_TABLE_ID=tblnsV4BVWe6N0Um`、`BITABLE_MATH_KNOWLEDGE_TABLE_ID=tbly3Xg5AEdFRIm4`。正式环境未配置，等待发布指令。

服务读取自建飞书表；10 分钟缓存刷新不等于实时同步源电子表格。后续更新继续只读核对选定字段，通过本地录入脚本保存。目录ID按来源行生成；源表插入、删除、排序时须先对照名称核对对应关系，不能直接按旧行号覆盖。重复保存 450 条验证为新增 0 条、更新 450 条。

脚本（项目目录中运行，需现有服务端环境变量和 Node.js 24）：

```sh
TS_NODE_PROJECT=tsconfig.node.json node -r ts-node/register scripts/math-knowledge-table.cjs WORK --create
TS_NODE_PROJECT=tsconfig.node.json node -r ts-node/register scripts/math-knowledge-table.cjs WORK --serve
TS_NODE_PROJECT=tsconfig.node.json node -r ts-node/register scripts/math-knowledge-verify.cjs WORK --verify
```

`WORK` 为本地绝对工作目录。录入服务仅监听 127.0.0.1 的临时随机地址，校验同源请求、10 个目录字段和来源链接，按目录ID更新自建表。读完后关闭服务。核验脚本读取自建表并写入数量、匹配样例与耗时记录；`--apply` 创建明确标记的非客户展示样例，`--cleanup` 清除样例。脚本不发布应用。
