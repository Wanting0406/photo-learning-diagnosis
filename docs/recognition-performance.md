# 识别性能与复用

模型为平台 AI 图片理解能力（当前豆包）；不压缩或降低原图分辨率。

## 分段计时

服务端结构化日志 event=diagnosis_timing，包含服务端生成的 request 关联编号、mode、stage、durationMs、ok；不包含图片、学生姓名、备注、模型输出或凭证。

- taskLookupMs / taskCreateMs：飞书任务查重、创建。
- photoResolveMs：原图输入或识别任务照片引用解析；冷缓存时包含飞书下载。
- modelMs：完整模型请求，包含必要时的一次截断恢复。
- photoArchiveMs：原图存入飞书；识别阶段与模型并行，最多两张同时上传。
- mappingReadMs / diagnosisSaveMs：产品映射读取、诊断记录保存。
- taskSaveMs / finalSaveMs：任务中间结果、最终状态保存。
- diagnosis_timing_summary：各阶段汇总与 serverTotalMs；并行阶段不能相加当作总耗时。
- diagnosis_model_usage：任务关联编号、输入输出 token 数（上游返回时）、预算、是否截断。
- diagnosis_client_timing：jobId、photoReadMs、submitMs、visibleMs。由前端结果渲染后的 effect 上报，属于客户端观测值；submitMs 包括网络传输和服务端创建任务，并非纯上传时间，visibleMs 包括轮询等待，不是精确屏幕绘制计时。刷新恢复的任务不伪造开始时间。

任务结果保留截至最终保存前的 timings 快照；finalSaveMs 与 serverTotalMs 在最终保存完成后写结构化日志。客户端计时接口校验登录、角色、任务归属和数值范围，采集失败不阻止报告显示。

## 输出预算

已批改识别：单张从 2400 token 起，每多一张增加 900，最高 6000。预批改、混合照片和完整诊断保留 6000 上限，以简洁提示约束重复描述与长段落，不删题或省略存疑题。

低预算响应被上游标记 length 时，只在原有 180 秒总期限内以 6000 预算恢复一次；不会接受截断 JSON，也不会盲目重试网络错误。简短输出不保证固定提速比例，应同时观察漏题、误判、失败率和耗时分位数。

## 状态缓存

缓存飞书已持久保存的任务记录：running 5 秒、终态 15 秒，上限 256 条；同实例同时读取同一任务只调用一次飞书。每次读取缓存后仍验证提交用户。任务写入前后失效缓存，旧的在途读取不能覆盖新缓存。跨实例最多会有短暂状态陈旧，飞书仍为事实来源。

## 照片与识别复用

识别成功后，任务的结果列以 diagnosis-v2 封装结果、原图附件 token、原始表单上下文及计时；对外接口仅返回结果、可复用标志及计时，不返回附件 token 或内部封装。旧版结果列仍可读取。

诊断可以提交 recognitionJobId 和空 photos。服务端核验源任务归属、已完成状态、识别类型与学生/年级/学科/备注一致性，然后恢复照片，并将源识别作为有待核对的证据传给模型；用户确认的错题清单仍优先。修改照片或表单会清除前端引用。

同实例照片缓存最多 32 组、48 MiB 的保守字符串估算容量，10 分钟有效。缓存未命中时通过已存的飞书附件 token 恢复原图；诊断记录直接使用已有 token，不再上传一次。附件已删除或不可下载时明确失败，需重新识别；不依赖内存缓存保证附件永久有效。

照片归档失败不会丢失识别结果，可复用标志为 false，前端后续诊断按原流程携带照片。旧页面和旧任务继续支持完整照片提交。只有识别、没有诊断的照片也会被归档；应纳入飞书数据留存管理。

## 验证

单元测试覆盖跨用户引用拒绝、上下文变化、缓存到期/并发/旧读取竞态、冷暖照片复用、归档失败回退、旧请求兼容、计时字段校验和输出截断恢复。

`test/diagnosis-live.cjs --apply --model PHOTO` 使用非客户测试图验证真实识别、重建服务实例后的照片恢复、完整诊断和附件字节一致性，并断言照片只上传一次；清理本次生成的任务与诊断记录。

2026-09-10：21 项单元测试、全量 lint/类型检查通过。真实示例卷完成冷缓存集成验证：识别服务端 7.742 秒，诊断服务端 24.255 秒，附件上传总计一次。浏览器同图完成两阶段操作，客户端识别 9.124 秒、诊断 26.647 秒，计时上报成功、报告已保存。上述是小型合成测试图的单次观测，不是复杂试卷的性能保证，也不是优化前后的对照结论。
