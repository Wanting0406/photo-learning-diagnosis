# 课程目录预加载与共享缓存

日期：2026-09-18。实现与验证完成，尚未发布。

## 变化

- 学情规划在开始识别资料时，按已填写的学科预读目录。报告生成仍等待识别证据和目录均就绪，不增加模型调用，也不改变匹配范围。
- 拍照分析原有的目录预读保持不变。两类流程现在复用同一个 FeishuService 对应的目录缓存及并发读取，减少不同模块重复拉取。
- 新增 `catalogWaitMs` 日志，记录识别结束后实际还需等待目录的时间。`catalogMs` 是目录读取完整耗时，两者有重叠，不能相加。

## 缓存规则

| 缓存年龄 | 处理 |
| --- | --- |
| 不足 5 分钟 | 直接返回完整缓存 |
| 5 至 10 分钟 | 返回缓存，同时由本次访问触发后台刷新；并发只刷新一次 |
| 达到 10 分钟或没有缓存 | 等待完整目录读取，成功后替换；失败不返回过期目录 |

刷新只在所有分页成功后替换旧目录。后台失败时退避 30 秒，旧目录最多使用到原来的 10 分钟有效期，不因失败续期。无需定时器，也不会无访问持续请求飞书。

缓存按飞书客户端及表格配置隔离，仅在同一服务进程内共享。进程重启、不同实例、首次访问或长时间闲置后仍可能冷加载。本次未引入跨实例或磁盘持久化缓存，未改产品表的 60 秒缓存。

## 验证

- 54 项相关测试通过，覆盖识别与预读重叠、并发合并、后台刷新、失败退避、硬过期、分页失败不保存半份目录及模块间共享。
- `npm run lint`、生产构建、`git diff --check` 均通过。
- 实际飞书只读验证：5,059 条数学课程条目；两个模块并发冷读取共用 12 次分页请求，耗时 13,517 毫秒；之后缓存读取耗时低于 1 毫秒，无新增飞书请求。
- 没有新增模型调用，没有创建或修改业务记录。
- 新本地服务正常启动；已保存合成规划的受登录保护读取接口返回 HTTP 200。

本次验证不等同于线上端到端提速统计。冷加载本身没有变快，收益来自与识别并行、模块共享和有效期内后台刷新。发布后可对比 `catalogWaitMs`、`evidenceMs` 与 `serverTotalMs` 确认实际收益。
